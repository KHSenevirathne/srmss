-------------------------------------------------------------------------------
 2. DETAILED WEEKLY BREAKDOWN
-------------------------------------------------------------------------------

 ---------------------------------------------------------------------------
 WEEK 1  |  18 May (Mon) - 24 May (Sun)  |  RESEARCH & REQUIREMENTS
 ---------------------------------------------------------------------------
  - Define the problem: manual, spreadsheet-based route planning in depots.
  - Study existing transport / fleet-management solutions and best practice.
  - Identify target users: Admin, Supervisor, Operator, Driver.
  - Gather and document functional requirements:
        * route & stop planning, scheduling with conflict detection,
          fleet & driver records, fuel/maintenance logs, dashboard,
          reporting with PDF export, role-based access.
  - Capture non-functional requirements: security, usability, performance.
  - Decide technology stack (Laravel + Livewire + Flux UI).
  - Output: Requirements Specification document.

 ---------------------------------------------------------------------------
 WEEK 2  |  25 May (Mon) - 31 May (Sun)  |  PLANNING & SYSTEM DESIGN
 ---------------------------------------------------------------------------
  - Produce project plan, task breakdown and this timeline.
  - Design the database schema (routes, stops, vehicles, drivers, schedules,
    trips, fuel logs, maintenance logs, users, roles, audit logs).
  - Draw ER diagram, use-case diagram and high-level architecture.
  - Design role / permission matrix (Admin, Supervisor, Operator, Driver).
  - Define the UI design system (colours, typography, components) in app.css.
  - Wireframe key screens: dashboard, route manager, schedule board, reports.
  - Set up project skeleton, Git repository and local dev environment.
  - Output: Design document + initialised codebase.

 ---------------------------------------------------------------------------
 WEEK 3  |  01 Jun (Mon) - 07 Jun (Sun)  |  CORE DEVELOPMENT (Part 1)
 ---------------------------------------------------------------------------
  - Authentication & authorisation (Fortify, two-factor, password confirm).
  - User management and role assignment (Spatie permissions).
  - Route and stop management (ordered stops, distance, interactive map).
  - Vehicle and driver records with search, filtering and validation.
  - Fuel and maintenance logging with "service due" logic and access control.
  - Output: Working authentication + core data-management modules.

 ---------------------------------------------------------------------------
 WEEK 4  |  08 Jun (Mon) - 14 Jun (Sun)  |  CORE DEVELOPMENT (Part 2) + TEST
 ---------------------------------------------------------------------------
  - Scheduling module with automatic conflict detection.
  - Central trips board with filtering and status management.
  - Dashboard: live trip status, fleet utilisation, network map, alerts.
  - Reporting engine: operational, driver-utilisation and cost reports.
  - PDF export for reports (DomPDF).
  - Activity / audit logging for create, update and delete actions.
  - UI polish: icon chips, consistent styling, JetBrains Mono font.
  - Begin Testing & QA (overlaps from 11 Jun): unit and feature tests (Pest),
    manual test checklist, access-control verification.

 ---------------------------------------------------------------------------
 WRAP-UP  |  15 Jun (Mon) - 16 Jun (Tue)  |  FIX, DOCUMENT, DEPLOY, SUBMIT
 ---------------------------------------------------------------------------
  - Fix defects found during testing; refine security settings & 2FA.
  - Restrict profile / security settings access by role (driver lock-down).
  - Final regression test pass and lint check.
  - Complete documentation (user guide, report, diagrams).
  - Prepare deployment package (InfinityFree) and deploy.
  - Final review and coursework submission.
